# Mehrsprachigkeit (i18n)

**Stand:** 2026-06-27 · Umgesetzt für die Website (nicht die mobile App).

Die Website ist in **6 Sprachen** verfügbar: Deutsch (Standard), Englisch, Türkisch,
Arabisch (RTL), Russisch, Ukrainisch. Ziel ist, die Zugangshürde für nicht
muttersprachlich deutsche Mieter:innen zu senken – der Betrieb bleibt deutschlandbezogen.

## Was übersetzt wird – und was bewusst Deutsch bleibt

**Übersetzt:** die gesamte UI (Startseite, Upload, Teaser, Bericht-Rahmen, Brief-Modal,
Kontaktformular, FAQ, Footer, Fehlermeldungen) **und** die Rechtstexte
(Impressum/Datenschutz/AGB) als *unverbindliche* Übersetzung.

**Bewusst Deutsch (NICHT übersetzt):**
- **Analyse-Ergebnis-Inhalte** (Fehler-Titel/-Beschreibung, Zusammenfassung, Rechtsgrundlage,
  Beleg) – kommen von der KI und beziehen sich auf die deutsche Abrechnung/Rechtslage.
- **Generierte Schreiben** + **Mail-Betreff** – gehen an einen deutschen Vermieter.
- **API-Fehlermeldungen** (Serverantworten) – bleiben vorerst deutsch (Follow-up: Error-Codes).

Auf Nicht-Deutsch-Rechtstexten erscheint der Hinweis: „Rechtlich maßgeblich ist ausschließlich
die deutsche Fassung."

## Architektur (`next-intl`)

- **Routing:** `[locale]`-Segment, `localePrefix: 'as-needed'` → Deutsch bleibt auf `/`,
  andere Sprachen unter `/en`, `/tr`, `/ar`, `/ru`, `/uk`. Middleware (`src/middleware.ts`)
  erkennt die Sprache (Cookie `NEXT_LOCALE` → `Accept-Language` → Default `de`).
- **Konfig:** `src/i18n/{routing,navigation,request}.ts`. `next.config.mjs` ist mit
  `createNextIntlPlugin()` umschlossen.
- **Layout:** `src/app/[locale]/layout.tsx` setzt `<html lang dir>` (`dir="rtl"` für `ar`),
  `NextIntlClientProvider`, per-Locale-Metadaten inkl. **hreflang** + `x-default` und JSON-LD.
- **Texte:** `messages/{de,en,tr,ar,ru,uk}.json`. **`de.json` ist die Quelle der Wahrheit.**
  Komponenten nutzen `useTranslations`. Listen/Arrays via `t.raw(...)`.
- **Interne Links/Navigation:** immer über `@/i18n/navigation` (lokalisierte `Link`/`router`).
- **Sprachumschalter:** `src/components/LocaleSwitcher.tsx`, oben rechts in der Nav.
- **SEO:** `sitemap.ts` listet alle Locale-URLs mit hreflang-Alternates; `robots.ts` sperrt
  `/ergebnis` und `/*/ergebnis`. Das OG-Bild bleibt bewusst in der deutschen Markenvariante
  (Satori-Default-Font deckt kein Arabisch/Kyrillisch ab).
- **RTL:** richtungsabhängige Tailwind-Utilities sind logisch (`ps/pe`, `ms/me`, `border-s/e`,
  `text-start`), damit das Layout für Arabisch spiegelt.

## Eine weitere Sprache hinzufügen

1. Locale-Code in `src/i18n/routing.ts` (`locales`) und `localeNames` ergänzen (RTL zusätzlich
   in `RTL_LOCALES`).
2. `messages/<code>.json` anlegen – dieselben Schlüssel wie `de.json`, Werte übersetzen.
   Gesetzeskürzel (BetrKV, HeizkV, BGB, BGH, RDG, UStG, MStV) als Eigennamen belassen.
3. Parität prüfen (siehe unten). Fertig – Routing/Sitemap/hreflang ziehen automatisch nach.

## Qualitäts-/Review-Status

- **Deutsch** = Quelle. **Englisch** = hochwertig (von Claude).
- **Türkisch/Arabisch/Russisch/Ukrainisch** = **KI-Erstübersetzung** (Marker `_meta.status = "ai-draft"`
  in jeder Datei). **Vor Launch von Muttersprachler:innen prüfen lassen**, besonders die Rechtstexte.

## Schlüssel-Parität prüfen

```bash
node -e "const flat=(o,p='')=>Object.entries(o).flatMap(([k,v])=>v&&typeof v==='object'&&!Array.isArray(v)?flat(v,p+k+'.'):[p+k]);const de=new Set(flat(require('./messages/de.json')).filter(k=>!k.startsWith('_meta')));for(const l of ['en','tr','ar','ru','uk']){const s=new Set(flat(require('./messages/'+l+'.json')).filter(k=>!k.startsWith('_meta')));const miss=[...de].filter(k=>!s.has(k));console.log(l+': '+(miss.length?('FEHLT '+miss.join(',')):'OK'));}"
```
